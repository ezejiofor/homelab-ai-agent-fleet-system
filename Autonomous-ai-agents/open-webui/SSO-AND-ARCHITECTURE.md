# Open WebUI — SSO + Architecture Runbook

`https://open-webui.georgehomelab.com` is the chat frontend for the agent
fleet. It does not host an LLM itself — it speaks the OpenAI-compatible
protocol to **Hermes**, which routes requests to Gemini 2.5 Flash Lite (or
any other configured backend).

End-to-end flow:

```
Browser ──┐
          ▼
  Istio ingress-gateway (homelab-gateway, *.georgehomelab.com TLS)
          │
          ▼
  oauth2-proxy-open-webui  (Keycloak realm `open-webui`, edge SSO)
          │   • Google / GitHub federated login
          │   • session cookie _oauth2_proxy
          │   • forwards X-Forwarded-Email / X-Forwarded-Preferred-Username
          ▼
  open-webui  (Python/FastAPI)
          │   • trusts X-Forwarded-* headers → auto-creates / signs in user
          │   • DEFAULT_USER_ROLE=user, ENABLE_SIGNUP=false
          ▼
  hermes:9120/v1  (OpenAI-compat API server, bearer token)
          │   • model: hermes-agent
          ▼
  Gemini 2.5 Flash Lite  (via GEMINI_API_KEY/GOOGLE_API_KEY in hermes-secrets)
```

---

## SSO model — three layers

| Layer | Enforced by | Cookie / token | Purpose |
|---|---|---|---|
| **1. Edge OIDC** | oauth2-proxy + Keycloak realm `open-webui` | `_oauth2_proxy` (encrypted session) | Anyone reaching the URL must be logged in via Google or GitHub *through Keycloak* |
| **2. Trusted-header auto-login** | Open WebUI `WEBUI_AUTH_TRUSTED_*` env | Open WebUI session token | Open WebUI auto-creates / logs in the user matching `X-Forwarded-Email`. No second password prompt. |
| **3. Open WebUI local app** | Open WebUI's own user/role model | Same session token | Per-user chats, admin-only settings, model picker |

**Why stack edge OIDC AND trusted-header?**

- L1 alone would mean an internal cluster pod could reach Open WebUI directly with no auth. STRICT mTLS PeerAuth + the ingress-only NetworkPolicy block that path, but defense-in-depth wants a second check.
- L2 alone (Open WebUI's own OIDC) would expose Open WebUI's auth surface publicly — any Open WebUI CVE in the auth code path is reachable from the internet. Edge oauth2-proxy isolates it.
- Stacked: oauth2-proxy is the only inbound path; once a request reaches Open WebUI with `X-Forwarded-Email` set, it has *by construction* passed Keycloak. Open WebUI doesn't need its own OIDC client or password store.

## Critical environment variables

Set in `deployment.yaml`:

```yaml
OPENAI_API_BASE_URL = "http://hermes.agents-system.svc.cluster.local:9120/v1"
OPENAI_API_KEY      = <from Secret hermes-secrets, key API_SERVER_KEY>
WEBUI_URL           = "https://open-webui.georgehomelab.com"

# Trusted-header SSO (auto-login from oauth2-proxy)
WEBUI_AUTH_TRUSTED_EMAIL_HEADER = "X-Forwarded-Email"
WEBUI_AUTH_TRUSTED_NAME_HEADER  = "X-Forwarded-Preferred-Username"

DEFAULT_USER_ROLE = "user"      # auto-created users get chat access
ENABLE_SIGNUP     = "false"     # local password signup form OFF
ENABLE_OLLAMA_API = "false"     # we don't run Ollama
```

Set in oauth2-proxy overlay's `deployment-patch.yaml` (the env that makes the trusted-header path work):

```yaml
OAUTH2_PROXY_PASS_USER_HEADERS         = "true"   # forwards X-Forwarded-Email/User
OAUTH2_PROXY_PASS_AUTHORIZATION_HEADER = "false"  # don't pass OIDC bearer (Open WebUI rejects it as session token)
OAUTH2_PROXY_SET_AUTHORIZATION_HEADER  = "false"  # ditto
OAUTH2_PROXY_PASS_HOST_HEADER          = "false"  # use upstream URL host so Istio routes via mTLS cluster
```

## Bring-up checklist (greenfield)

1. **Realm** — add `open-webui` to `gen_realms.py` TOOLS, run `python3 gen_realms.py`, add the JSON to `keycloak/kustomization.yaml`'s `configMapGenerator`. `kubectl replace -n keycloak cm/keycloak-realm-import -f -` and restart Keycloak pods so it imports with `${GOOGLE_CLIENT_ID}` / `${GOOGLE_CLIENT_SECRET}` resolved from `keycloak-idp-secrets` (admin-API import does **not** resolve those — only file-import on pod startup does).
2. **Google OAuth redirect URI** — add `https://keycloak.georgehomelab.com/realms/open-webui/broker/google/endpoint` in console.cloud.google.com.
3. **K8s Secret for oauth2-proxy** — `python3 kubernetes-addons/0-boostrap/oauth2-proxy/overlays/open-webui/setup-secret.py` (queries Keycloak admin API for `oauth2-proxy` client_secret).
4. **Apply oauth2-proxy overlay** — `kubectl apply -k kubernetes-addons/0-boostrap/oauth2-proxy/overlays/open-webui/`.
5. **Deploy Open WebUI** — let ArgoCD sync (`agent-open-webui` Application from the `agent-fleet-system` ApplicationSet).
6. **Hermes API server** — confirm `API_SERVER_ENABLED=true` in `kubernetes-addons/Autonomous-ai-agents/hermes/configmap.yaml` and `API_SERVER_KEY` populated in Vault.
7. **DNS** — `open-webui.georgehomelab.com` → Istio ingress LB IP.
8. **Browser** — visit URL, sign in via Google. First user lands as `user`. Promote to admin in *Admin Settings → Users* if desired.

## End-to-end recovery checklist

When `https://open-webui.georgehomelab.com/` does *not* work, walk down the chain:

1. **`upstream connect error or disconnect/reset before headers`** — Envoy at the Istio gateway can't reach oauth2-proxy or open-webui. Check `kubectl -n agents-system get pods -l app.kubernetes.io/name=open-webui`. If 1/2 (only istio-proxy ready), inspect `kubectl -n agents-system logs <pod> -c open-webui` for crash loops.
2. **`token exchange failed: oauth2: "unauthorized_client"`** — K8s `oauth2-proxy-open-webui` Secret drifted from Keycloak realm `oauth2-proxy` client. Re-run `setup-secret.py` and restart `deploy/oauth2-proxy-open-webui`.
3. **`Could not send authentication request to identity provider`** — Realm has unresolved `${GOOGLE_CLIENT_ID}` placeholder (admin-API import bug). Delete realm, ensure configmap has `open-webui-realm.json`, restart Keycloak pods so file-import resolves env vars.
4. **Spinner forever, no model in dropdown** — Open WebUI calling hermes:9120 fails. Common causes:
   - `OPENAI_API_KEY` mismatch with `hermes-secrets.API_SERVER_KEY` → re-check VSO sync.
   - aiohttp DNS cache stale on first start → `kubectl -n agents-system rollout restart deploy/open-webui`.
   - oauth2-proxy injecting `Authorization: Bearer <id-token>` upstream → confirm `PASS_AUTHORIZATION_HEADER=false` and `SET_AUTHORIZATION_HEADER=false` in the overlay.
5. **`upstream connect error … reset reason: connection termination` *after* successful Keycloak login** — oauth2-proxy is forwarding the public Host header (`open-webui.georgehomelab.com`) and Istio's outbound vhost on port 8080 only knows the internal name. Falls through to PassthroughCluster (no mTLS). Set `OAUTH2_PROXY_PASS_HOST_HEADER=false`.
6. **`filter_chain_not_found / NR` in open-webui istio-proxy access log** — Service port lacks `appProtocol: http`. Add it so Istio creates the HTTP filter chain on the inbound mTLS listener.
7. **Login completes but Open WebUI keeps showing signup form** — `ENABLE_SIGNUP=false` and trusted-header env vars not set on the running pod. Verify with `kubectl get pod ... -o jsonpath='{.spec.containers[0].env}'`.

## Operational commands

```bash
# Tail oauth2-proxy logs (skip noise)
OWP=$(kubectl -n agents-system get pod -l app.kubernetes.io/instance=oauth2-proxy-open-webui -o jsonpath='{.items[0].metadata.name}')
kubectl -n agents-system logs $OWP -c oauth2-proxy --tail=50 | grep -vE "kube-probe|/ping|/ready"

# Tail Open WebUI app logs
OWP2=$(kubectl -n agents-system get pod -l app.kubernetes.io/name=open-webui -o jsonpath='{.items[0].metadata.name}')
kubectl -n agents-system logs $OWP2 -c open-webui --tail=50

# Verify Open WebUI can reach Hermes /v1/models
kubectl -n agents-system exec $OWP2 -c open-webui -- python3 -c '
import os, urllib.request, json
req = urllib.request.Request(os.environ["OPENAI_API_BASE_URL"]+"/models", headers={"Authorization":"Bearer "+os.environ["OPENAI_API_KEY"]})
print(json.load(urllib.request.urlopen(req, timeout=8)))'

# Verify K8s oauth2-proxy secret matches Keycloak realm
KC_URL=https://keycloak.georgehomelab.com
TOKEN=$(curl -sk -X POST "$KC_URL/realms/master/protocol/openid-connect/token" \
  -d "username=$(kubectl -n keycloak get secret keycloak-credentials -o jsonpath='{.data.admin-user}'|base64 -d)" \
  -d "password=$(kubectl -n keycloak get secret keycloak-credentials -o jsonpath='{.data.admin-password}'|base64 -d)" \
  -d "grant_type=password" -d "client_id=admin-cli" | jq -r .access_token)
CID=$(curl -sk -H "Authorization: Bearer $TOKEN" "$KC_URL/admin/realms/open-webui/clients?clientId=oauth2-proxy" | jq -r '.[0].id')
KC=$(curl -sk -H "Authorization: Bearer $TOKEN" "$KC_URL/admin/realms/open-webui/clients/$CID/client-secret" | jq -r .value)
K8=$(kubectl -n agents-system get secret oauth2-proxy-open-webui -o jsonpath='{.data.client-secret}' | base64 -d)
[ "$KC" = "$K8" ] && echo MATCH || echo MISMATCH

# Re-sync K8s oauth2-proxy secret if MISMATCH
yes y | python3 kubernetes-addons/0-boostrap/oauth2-proxy/overlays/open-webui/setup-secret.py
kubectl -n agents-system rollout restart deploy/oauth2-proxy-open-webui

# Reset Open WebUI database (destroys all chats, users, settings — use with care)
kubectl -n agents-system delete pvc open-webui-data
kubectl -n argocd patch app agent-open-webui --type merge -p '{"operation":{"sync":{}}}'
```

## Logout

- **Open WebUI logout button** — clears Open WebUI's own session token only. The `_oauth2_proxy` cookie is still valid, so the next visit auto-logs you back in via trusted-header SSO.
- **Full logout** — visit `https://open-webui.georgehomelab.com/oauth2/sign_out`. This kills the oauth2-proxy session. Open WebUI session is collateral. (For a true Keycloak SSO-wide logout that also signs you out of Google, use `https://keycloak.georgehomelab.com/realms/open-webui/protocol/openid-connect/logout` with appropriate redirect params.)
- **Closing the browser** — clears the `_oauth2_proxy` cookie since cookie-expiry is session-bound by default; next visit re-authenticates.

## Promoting users to admin

The first user gets `user` role (per `DEFAULT_USER_ROLE`). To promote:

1. Sign in as an existing admin (the local admin you created during initial bootstrap, before trusted-header was enabled).
2. *Admin Settings → Users → \<user> → Role → admin*.

Or, if you didn't create an initial local admin, edit the SQLite DB directly (last resort):

```bash
OWP2=$(kubectl -n agents-system get pod -l app.kubernetes.io/name=open-webui -o jsonpath='{.items[0].metadata.name}')
kubectl -n agents-system exec -it $OWP2 -c open-webui -- sqlite3 /app/backend/data/webui.db \
  "UPDATE user SET role='admin' WHERE email='terranetes@gmail.com';"
```
